# Feedback and diagnostic privacy

Use the private channel the repository owner designates before inviting testers.
The channel is pending. Confirm that testers can use it without posting project
details publicly.

Include the Bashwink release version and checksum, macOS version/build, backend,
whether the problem occurs in a disposable sample, the expected result, and the
observed error. Describe permission or confinement failures separately from UI bugs.

Review attachments before sharing. Remove provider keys, authorization headers,
environment dumps, model prompts containing project data, personal paths, and session
databases. Prefer a short synthetic reproduction and selected redacted evidence
entries. Keep security-sensitive reports private.
